We treat AI agents as first-class readers of our documentation. The same Taiga UI knowledge is published in a few complementary shapes, so whatever your assistant can consume — a flat context file, a query server, or a reusable skill — it can reach the current, version-correct API instead of guessing from memory.

New to wiring AI into your editor? Drop llms-full.txt into your model's context for a zero-setup start, or connect the MCP server for on-demand queries.

Which layer do I need?

These aren't competing options — they are a stack of roles over one body of knowledge.

  • llms.txt / llms-full.txt — reach for it when you just want to drop the current API into any model's context window.
  • @taiga-ui/mcp — reach for it when your agent can call tools and should ask for one component's exact, current API on demand.
  • Agent skills — reach for them when you want the agent to follow a proven Taiga workflow and know what to double-check.
llms-full.txt is the generated data, @taiga-ui/mcp is a query interface over that same data, and skills are the method that consumes it. When they disagree, the live source wins.
