A grid for icons, emoji or anything else you project into it — the same bargain as tui-data-list . It owns layout, keyboard navigation and sticky group headings, and nothing else: no data, no selection, no search. You render the cells, so a click does whatever you bind to it.

The simplest case is one *ngFor of [tuiIconOption] buttons. Need sections? Wrap them in tui-icon-group . Need search? Filter your own array. Need tabs? Bring tuiTabs and point [tuiIconTabs] at the list.

tui-icon-list

Lays projected options out in a grid of eight columns and drives roving-tabindex keyboard navigation over them. Scrolling belongs to whatever wraps it — usually tui-scrollbar — which the list finds through TUI_SCROLL_REF . Column count comes from TUI_ICON_LIST_OPTIONS , since two-dimensional arrows need it in TypeScript and not only in CSS.

It is deliberately not virtualized. Windowing projected content would mean owning the data, which is exactly what this component refuses to do — render fewer items yourself if a set gets too large.

tui-icon-group

Heading text. It sticks to the top of the scroll area while the group is on screen and leaves with it. Groups are optional — options can sit straight in the list.

[tuiIconOption]

Marks an element as a cell: role="option" plus the grid styling and the tab stop. It carries no value and emits nothing.

The cell is a plain flex box, so its content is whatever you put there — a glyph, a tui-icon or an <img> . The last one is how a picker stops depending on the platform emoji font: the Twemoji example renders every cell from @twemoji/api assets, and pairs them with [content] so the closed field shows the same image. An image has no font size to inherit, so give it a size of its own.

Sizing

The grid has an intrinsic width — its cells are minmax(var(--t-cell), 1fr) wide (plus the option margin) and the host sets no width of its own. That is what lets a shrink-to-fit container measure it: a dropdown with tuiDropdownLimitWidth="auto" , or a tui-dialog with size="auto" , wraps around the grid instead of collapsing it. Inside a container that has a width of its own the columns stretch to fill it, while the cells keep their size and spread apart. A cell is 2rem with a 1.5rem glyph; override --t-cell to change it.

Note that tui-textfield pins its dropdown to the field width by default, so a picker panel inside one needs tuiDropdownLimitWidth="auto" — otherwise eight columns get squeezed into the width of the input.

Using it as a data list

Stack tuiOption with a [value] onto the cells and the list starts reporting those values as its options, which is the whole contract tuiComboBox and friends need. Clicks then travel the normal route — the option tells TUI_DATA_LIST_HOST , the textfield writes the value and closes the dropdown — so no click handler of your own is involved. Cells without a value cost nothing and simply do not appear among the options.

Both option directives are re-exported from TuiIcons , so a single import is enough. Without them in scope the directive silently never instantiates and the list reports nothing.

[tuiIconTabs]

Goes on a tuiTabs nav and takes the list, e.g. [tuiIconTabs]="list" with #list="tuiIconList" . Tabs and groups are paired by index: clicking the nth tab scrolls to the nth group, and scrolling to the nth group lights up the nth tab. It lives on the nav rather than on each tab because both usually come out of an *ngFor , where a per-tab binding to a group instance would be evaluated before @ViewChildren resolve.

Keyboard

Move around the grid. Arriving from outside — a search field, say — enters at the first option. First and last option of the current group.
